# Test and development dependencies.
#
#     pip install -r requirements-dev.txt
#
# ---------------------------------------------------------------------------
# Why this file does NOT simply compose the three deploy manifests
# ---------------------------------------------------------------------------
# The intended shape was `-r backend/requirements.txt`, `-r etl/...` and
# `-r agent/...`, keeping each deploy manifest authoritative. That combination
# is unsatisfiable today and pip exits with ResolutionImpossible:
#
#   backend/requirements.txt  boto3==1.43.4
#   etl/requirements.txt      boto3==1.43.4
#   agent/...                 bedrock-agentcore==1.19.0 -> boto3>=1.43.31
#                             strands-agents==1.50.2    -> boto3>=1.26.0,<2
#
# Each Lambda deployment package is built separately, so this never breaks a
# deploy -- but one combined test environment cannot honour both pins. The
# agent's floor wins here, because its packages are imported at collection
# time by six test modules and cannot be skipped.
#
# Consequence to be aware of: the test environment runs a newer boto3 than
# backend/ and etl/ deploy with. Aligning boto3 across the three deploy
# manifests would let this file go back to pure composition.
# ---------------------------------------------------------------------------

# Agent runtime deps. Required, not optional: tests/test_agent_main.py,
# test_github_tool.py, test_gitlab_tool.py, test_kiro_data_tool.py,
# test_gitlab_provider_properties.py and test_ssm_token.py import agent code,
# which imports bedrock_agentcore, pydantic and strands at module top level
# with no test stubbing them. Omitting this fails pytest *collection* with six
# errors, before a single assertion runs.
-r agent/app/GitCorrelationAgent/requirements.txt

# conflict explained above. `requests` matches those manifests exactly; boto3
